# 「一记」Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a mobile-first web app where freelancers log a job in 3-5 seconds by tapping preset tiles, tracking what/when/how much/where plus completion and payment state, with unpaid work ranked by how long it has been outstanding.

**Architecture:** React SPA with three tabs (速记 / 流水 / 未收款). All writes go to an IndexedDB outbox first with optimistic UI updates, then flush to Supabase serially and stop-on-error so foreign-key ordering holds. All money is integer cents client-side and `numeric(12,2)` server-side. Payment status is always derived from `payments`, never stored.

**Tech Stack:** React 19, TypeScript, Vite 8, Tailwind CSS v4, Supabase (Auth + PostgreSQL + RLS), TanStack Query 5, Zustand 5, Dexie 4, Vitest + Testing Library + fake-indexeddb

**Spec:** `docs/superpowers/specs/2026-09-12-yiji-design.md`

```ts
export type Cents = number

export class MoneyError extends Error {}

/** numeric(12,2) 的容量上限：99,999,999 元 */
export const MAX_CENTS = 99_999_999 * 100

const AMOUNT_PATTERN = /^\d+(\.\d{1,2})?$/

/**
 * 把用户输入解析为整数分。
 * 数字先经 toFixed(2) 转成定点字符串再拆位，避免 19.99 * 100 = 1998.999... 这类误差。
 * 超过两位小数直接抛错，不静默截断——静默截断会让用户以为记的是 0.005 元。
 */
export function toCents(input: string | number): Cents {
  let cleaned: string

  if (typeof input === 'number') {
    if (!Number.isFinite(input)) throw new MoneyError('金额必须是有限数字')
    if (input < 0) throw new MoneyError('金额不能为负')
    cleaned = input.toFixed(2)
  } else {
    cleaned = input.trim().replace(/^¥/, '').replace(/,/g, '')
  }

  if (cleaned === '') throw new MoneyError('金额不能为空')
  if (!AMOUNT_PATTERN.test(cleaned)) {
    throw new MoneyError('金额格式不正确，最多两位小数')
  }

  const [whole, frac = ''] = cleaned.split('.')
  const cents = Number(whole) * 100 + Number(frac.padEnd(2, '0'))

  if (cents > MAX_CENTS) throw new MoneyError('金额超出上限 99,999,999 元')
  return cents
}

export function fromCents(cents: Cents): number {
  return cents / 100
}

/** 展示用。负号放在 ¥ 前面，符合中文账单习惯。 */
export function formatYuan(cents: Cents): string {
  const sign = cents < 0 ? '-' : ''
  const abs = Math.abs(cents)
  const whole = Math.floor(abs / 100)
  const frac = String(abs % 100).padStart(2, '0')
  return `${sign}¥${whole.toLocaleString('zh-CN')}.${frac}`
}

/** 写入 Supabase numeric(12,2) 的边界转换 */
export function centsToNumeric(cents: Cents): string {
  return (cents / 100).toFixed(2)
}
```

| 提交 | 偏离 | 原因 |
| --- | --- | --- |
| `ea628fe` | 剥离逗号前先校验千分位分组（新增 `GROUPED_PATTERN`） | 原先 `replace(/,/g,'')` 无条件剥离，把逗号当小数点用的输入会被**静默放大 100 倍**写进 `numeric(12,2)`：`toCents('19,99')` → `199900`（¥1,999.00），用户本意是 ¥19.99。自定义金额输入框直接喂移动端原始键入，可达。`'1,000.50'` 照旧接受。 |

```ts
import type { Cents } from './money'

export type PaymentStatus = 'unpaid' | 'partial' | 'paid'

export const PAYMENT_STATUS_LABEL: Record<PaymentStatus, string> = {
  unpaid: '未收款',
  partial: '部分收款',
  paid: '已收款',
}

/**
 * 状态永远从金额派生，不落库。
 * 存字段就一定会和 payments 打架：改了收款忘了改状态，账就对不上。
 */
export function derivePaymentStatus(expectedCents: Cents, paidCents: Cents): PaymentStatus {
  if (paidCents <= 0) return 'unpaid'
  if (paidCents < expectedCents) return 'partial'
  return 'paid'
}

/** 还差多少。超额时归零，不返回负数。 */
export function outstandingCents(expectedCents: Cents, paidCents: Cents): Cents {
  return Math.max(0, expectedCents - paidCents)
}

/** 多收了多少，用于展示「多收 ¥X」。未超额时为零。 */
export function overpaidCents(expectedCents: Cents, paidCents: Cents): Cents {
  return Math.max(0, paidCents - expectedCents)
}
```

```ts
const MS_PER_DAY = 86_400_000

/**
 * 必须用本地时间拼装，不能用 toISOString()。
 * toISOString 返回 UTC 日期，在 UTC+8 的晚上会算成「明天」，
 * 导致当天记的活被标成拖欠 -1 天。
 */
export function toISODate(date: Date): string {
  const y = date.getFullYear()
  const m = String(date.getMonth() + 1).padStart(2, '0')
  const d = String(date.getDate()).padStart(2, '0')
  return `${y}-${m}-${d}`
}

export function todayISO(): string {
  return toISODate(new Date())
}

/**
 * 拖欠天数 = 今天 - 工作日期。
 * 未来日期（记「明天要干的活」）用 Math.max(0, ...) 兜住，
 * 与数据库侧 v_unpaid 的 greatest(0, ...) 保持一致。
 */
export function daysOverdue(workDate: string, today: string = todayISO()): number {
  const start = Date.parse(workDate)
  const end = Date.parse(today)
  if (Number.isNaN(start) || Number.isNaN(end)) throw new Error('日期格式不正确')
  return Math.max(0, Math.round((end - start) / MS_PER_DAY))
}

/** 往前推 n 天的 ISO 日期，用于「最近 30 天」筛选 */
export function cutoffISO(today: string, days: number): string {
  const date = new Date(`${today}T00:00:00`)
  date.setDate(date.getDate() - days)
  return toISODate(date)
}
```

```ts
import type { Cents } from './money'
import { cutoffISO } from './dates'

export interface TileSource {
  id: string
  name: string
  useCount: number
  lastUsedAt: string
}

export const DURATION_TILES = [
  { label: '0.5h', minutes: 30 },
  { label: '1h', minutes: 60 },
  { label: '2h', minutes: 120 },
  { label: '半天', minutes: 240 },
  { label: '全天', minutes: 480 },
] as const

export const FALLBACK_AMOUNT_CENTS: Cents[] = [50_000, 100_000, 300_000, 500_000]

/** 金额磁贴的回看窗口。Task 9 取历史时 import 这个值，避免两处各写一个 30。 */
export const AMOUNT_LOOKBACK_DAYS = 30

const AMOUNT_TILE_SLOTS = 4

/** 越常用越靠左；次数相同看最近使用。返回新数组，不改原数组。 */
export function sortTiles<T extends TileSource>(tiles: T[]): T[] {
  return [...tiles].sort(
    (a, b) =>
      b.useCount - a.useCount || Date.parse(b.lastUsedAt) - Date.parse(a.lastUsedAt),
  )
}

/**
 * 金额磁贴不建表，从最近 30 天历史按频次算 top4。
 * 历史不足时用固定档补齐，保证首次打开金额行不是空的。
 * ISO 日期字符串可直接按字典序比较，无需解析。
 */
export function topAmountTiles(
  records: { amountCents: Cents; workDate: string }[],
  today: string,
  slotCount: number = AMOUNT_TILE_SLOTS,
): Cents[] {
  const cutoff = cutoffISO(today, AMOUNT_LOOKBACK_DAYS)
  const freq = new Map<Cents, number>()

  for (const record of records) {
    if (record.workDate < cutoff) continue
    freq.set(record.amountCents, (freq.get(record.amountCents) ?? 0) + 1)
  }

  const ranked = [...freq.entries()]
    .sort((a, b) => b[1] - a[1] || a[0] - b[0])
    .map(([amount]) => amount)

  const result = ranked.slice(0, slotCount)
  for (const fallback of FALLBACK_AMOUNT_CENTS) {
    if (result.length >= slotCount) break
    if (!result.includes(fallback)) result.push(fallback)
  }
  return result
}
```

**这里刻意没有客户端的工作类型预置常量。** spec §3.1 与 §5.5 把预置的 7 种类型交给数据库的注册触发器（Task 5 的 `seed_preset_work_types`），客户端只负责把 `work_types` 表读出来渲染。再在客户端存一份同样的 7 个名字就成了第二个真相来源：改了 SQL 忘了改常量，两边会悄悄分叉。冷启动且离线时类型行为空是可达的，但那时 `+` 自学习磁贴仍可记下第一种类型，不需要预置兜底。

```ts
import type { Cents } from './money'

const MIN_DURATION_MINUTES = 1
const MAX_DURATION_MINUTES = 24 * 60

/** 返回 null 表示通过，返回字符串即错误文案（直接展示给用户） */
export function validateDuration(minutes: number | null): string | null {
  if (minutes === null) return null
  if (!Number.isInteger(minutes)) return '时长必须是整数分钟'
  if (minutes < MIN_DURATION_MINUTES) return '时长至少 1 分钟'
  if (minutes > MAX_DURATION_MINUTES) return '单条时长不超过 24 小时，请拆成两条'
  return null
}

/**
 * 收款超过应收是允许的——客户多付、含税差异都会出现。
 * 这里只拦非法值，超额由 UI 显示「多收 ¥X」而不是报错。
 *
 * 刻意不收 expectedCents：本来就没用到，而 derive.ts 的三个函数都收
 * (expectedCents, paidCents)，多一个反序的同名参数只会让人传错。
 * 与 expected 的比较全部归 derive.ts。
 */
export function validatePaymentAmount(paidCents: Cents): string | null {
  if (paidCents <= 0) return '收款金额必须大于 0'
  return null
}
```

**`v_unpaid` 三点语义（Task 3 与 Task 13 依赖，实施时不要「顺手修正」）：**

- `days_overdue` 的 `greatest(0, current_date - wr.work_date)` 兜住「记明天要干的活」这类未来日期，与 `dates.ts` 的 `daysOverdue()` 里 `Math.max(0, ...)` 对应。Task 4 的测试用同一天 / 过去 / 未来三组值锁死客户端这一侧。
- `outstanding_amount` **刻意没有** `greatest(0, ...)`。下方 `where wr.expected_amount > coalesce(p.paid_amount, 0)` 已经把足额和多付的行整条排除，返回行里 `outstanding_amount` 恒为正。多付是合法业务（客户多付、含税差异，见 Task 13 `validatePaymentAmount` 的注释），若为「对称」给它加上 `greatest(0,...)`，已收满的单子就会重新出现在未收款列表里。
- `security_invoker = true` 不能删。删掉后视图以创建者身份执行，底层表的 RLS 失效，任何登录用户都能读到别人的未收款。

**已知取舍：`days_overdue` 的「今天」取的是数据库的 `current_date`（Supabase 默认 UTC），不是设备本地日期。** 对 UTC+8 用户，本地 00:00–08:00 之间 `current_date` 还是昨天，于是未收款屏显示的拖欠天数会比实际少 1 天，`worst.days_overdue > 0` 的置顶警示也可能不出现。影响面有限：Task 13 内部用同一个值排序与展示，自身一致；Task 12 那条客户端算出来的 `days_overdue` 只填进 `PaymentSheet` 的 row，而弹层只读 `outstanding_amount`，不会显示，所以两个页面不会当场打架。

真要修，最小改动是让客户端算：Task 13 已经在 `UnpaidRow` 里拿到了 `work_date`，改成 `daysOverdue(row.work_date)` 并把排序挪到客户端，视图那列就只剩排序用途（而「按 `work_date` 升序」等价且与时区无关）。本计划选择先不做——用户就一个，凌晨看账的概率低，而少一个跨层契约改动就少一处出错机会。

```ts
import Dexie, { type Table } from 'dexie'

export type TableName =
  | 'clients'
  | 'work_types'
  | 'locations'
  | 'work_records'
  | 'payments'

export type OutboxOp = 'insert' | 'update' | 'delete'

export interface OutboxEntry {
  /** 自增主键。用它排序而不是时间戳——同一毫秒内入队两条时时间戳会相等，顺序就丢了 */
  seq?: number
  /** 客户端生成的行 UUID，既是目标表主键也是幂等键 */
  id: string
  op: OutboxOp
  tableName: TableName
  payload: Record<string, unknown>
  enqueuedAt: number
  attempts: number
  lastError?: string
}

export interface CachedRows {
  key: string
  rows: unknown[]
  fetchedAt: number
}

class YijiDB extends Dexie {
  outbox!: Table<OutboxEntry, number>
  readCache!: Table<CachedRows, string>

  constructor() {
    super('yiji')
    this.version(1).stores({
      outbox: '++seq, id, tableName',
      readCache: 'key',
    })
  }
}

export const db = new YijiDB()
```

```ts
import { db, type OutboxEntry, type OutboxOp, type TableName } from './db'

export const MAX_ATTEMPTS = 5

const BACKOFF_MS = [1_000, 5_000, 30_000, 120_000] as const

export function backoffDelay(attempts: number): number {
  return BACKOFF_MS[Math.min(attempts, BACKOFF_MS.length - 1)]
}

export interface EnqueueInput {
  id: string
  op: OutboxOp
  tableName: TableName
  payload: Record<string, unknown>
}

const enqueueListeners = new Set<() => void>()

/**
 * 订阅「有新条目入队」。调度器用它做到 spec §5.3 的「入队后立即试」，
 * 不必等兜底轮询。返回取消订阅函数。
 *
 * 用回调注册表而不是让 outbox 直接 import 调度器：outbox 是纯队列，
 * 不该知道同步策略，否则两者互相依赖、也没法单独测。
 */
export function onEnqueue(listener: () => void): () => void {
  enqueueListeners.add(listener)
  return () => {
    enqueueListeners.delete(listener)
  }
}

export async function enqueue(input: EnqueueInput): Promise<number> {
  const seq = await db.outbox.add({
    ...input,
    enqueuedAt: Date.now(),
    attempts: 0,
  })
  // 通知放在 add 之后：先通知再落库，会推一条还不存在的记录
  for (const listener of enqueueListeners) listener()
  return seq
}

export async function pendingCount(): Promise<number> {
  return db.outbox.count()
}

export async function pendingEntries(): Promise<OutboxEntry[]> {
  return db.outbox.orderBy('seq').toArray()
}

/**
 * 丢弃一条卡死的条目，给队列留一条出路。
 *
 * retryAll 对永久性失败无效——清零重推还是同一条错误，重新卡死；而串行遇错
 * 即停意味着这一条会堵住后面**所有**记录。此时唯一出路是把它从队列里摘掉。
 * 这一条的数据确实丢了，但那是用户在「整条队列永久停摆」和「丢掉这一条」之间
 * 自己做的选择，不是静默丢失——所以调用点必须先让用户看清是哪一条再确认
 * （Task 14 的红点展开面板）。
 */
export async function discard(seq: number): Promise<void> {
  await db.outbox.delete(seq)
}

/** 注入式推送函数，让 flush 逻辑能脱离 Supabase 单测 */
export type PushFn = (entry: OutboxEntry) => Promise<void>

export interface FlushResult {
  pushed: number
  stoppedAt?: OutboxEntry
}

/**
 * 串行 + 遇错即停。两个约束都不能松：
 *
 * 串行 —— clients 必须先于引用它的 work_records 到达，work_records 必须先于
 *         引用它的 payments 到达。并发推送会让外键找不到父行。
 * 遇错即停 —— 跳过失败项继续推后面的，同样会破坏依赖顺序。
 *
 * 代价是一条永久失败的条目会堵住整个队列，所以 attempts 达到 MAX_ATTEMPTS 后
 * 转红点、停自动重试，由用户在顶栏手动「立即重试」（走 retryAll 重置计数）。
 * 数据始终留在 IndexedDB，永不丢弃。
 */
export async function flushOnce(push: PushFn): Promise<FlushResult> {
  const entries = await db.outbox.orderBy('seq').toArray()
  let pushed = 0

  for (const entry of entries) {
    if (entry.attempts >= MAX_ATTEMPTS) {
      return { pushed, stoppedAt: entry }
    }
    try {
      await push(entry)
      await db.outbox.delete(entry.seq!)
      pushed++
    } catch (error) {
      const lastError = error instanceof Error ? error.message : String(error)
      const attempts = entry.attempts + 1
      await db.outbox.update(entry.seq!, { attempts, lastError })
      // 返回自增之后的值：调用方靠 attempts 判断「重试是否已耗尽」（转红点），
      // 回传旧值会让红点整整晚一个周期才亮
      return { pushed, stoppedAt: { ...entry, attempts, lastError } }
    }
  }

  return { pushed }
}

/** 用户点「立即重试」时调用：清零计数，让卡住的队列重新走一遍 */
export async function retryAll(push: PushFn): Promise<FlushResult> {
  await db.outbox.toCollection().modify({ attempts: 0, lastError: undefined })
  return flushOnce(push)
}
```

**已知缺口（已补一半）：永久失败的条目会堵死整条队列。** 串行遇错即停的代价是一个条目卡住就挡住后面所有记录；计划原本的对策是「立即重试」（`retryAll` 清零计数），但那对**永久性**失败无效——清零再推还是同一条错误，重新卡死。更麻烦的是 `flushOnce` 只留下 `error.message`，Postgres 的 23505（唯一约束）/23514（CHECK）与网络错误在前端形态完全一样，分不出「等会儿会好」和「这条永远过不去」。

可达场景（不是纯理论）：离线且本地磁贴缓存为空时，用户点 `[+]` 新建客户「张三」，生成新的本地 UUID；云端其实已经有「张三」——另一台设备建过，或本地缓存已过期。insert 走 `upsert onConflict: 'id'`，id 不撞，于是退化成 INSERT，撞上 `unique (user_id, name)` → 永久失败。此后该用户**所有**记录的同步全部停摆，界面上只有一个红点。而且即使跳过这条 insert，引用该本地 UUID 的 `work_records` 仍会撞外键——正解是在入队前按名字对账，属于设计改动，本计划不做。

本任务给出的出路是 `discard(seq)`：把卡住的那条从队列里摘掉。消费点在 Task 14——红点不再只把错误塞进 `title`（移动端 hover 不出来等于看不见），而是点开一个面板列出卡住的条目与原因，逐条「丢弃」。

补充两点实施期确认的事实：`supabasePush` 里**没有任何地方**把 23505 翻译成「已存在，改走选择」；`fetchAndCache` 只在**成功**读取后才写缓存，所以读取失败时缓存不会被填充。两点叠加意味着「外面没信号 → 冷启动 → 缓存空 → 新建客户」正是暴露面最大的路径，不是边角情形。

**`discard` 只能救「不相干」的那些条目**（Task 9 审查确认）：摘掉那条撞 23505 的 client insert 之后，引用同一本地 UUID 的 `work_records` insert 紧接着会撞 `references clients(id)`（23503），于是它成为下一条卡死条目，它的 payment 再跟着。也就是说这条工作记录与其收款**永久丢失**，只是队列本身活了。而且红点面板只在 `status === 'error'` 时渲染，摘掉一条之后新的队首要重新走完 1s/5s/30s/2min、攒够 5 次失败才再次变红——每处理一条要空等约 3 分钟。真要根治得在推送侧把 23505 翻译成「按 name 重新选中」并把后续 payload 里的本地 UUID 改写成服务端的，属于设计改动，本计划不做。

```ts
import { getSupabase } from './supabase'
import type { OutboxEntry } from './db'

export async function supabasePush(entry: OutboxEntry): Promise<void> {
  const supabase = getSupabase()
  const table = supabase.from(entry.tableName)

  if (entry.op === 'delete') {
    const { error } = await table.delete().eq('id', entry.id)
    if (error) throw error
    return
  }

  if (entry.op === 'update') {
    // 局部字段更新必须走 update。走 upsert 会把 payload 里没带的列写成 null，
    // 例如只想改 is_completed 却把 expected_amount 清空。
    const { error } = await table.update(entry.payload).eq('id', entry.id)
    if (error) throw error
    return
  }

  const { error } = await table.upsert(entry.payload, { onConflict: 'id' })
  if (error) throw error
}
```

```ts
import {
  MAX_ATTEMPTS,
  backoffDelay,
  flushOnce,
  onEnqueue,
  pendingEntries,
  retryAll,
  type FlushResult,
} from './outbox'
import { supabasePush } from './supabasePush'
import { useSyncStore } from '@/features/sync/syncStore'

/** 队列空时的轮询节奏。只是兜底，联网与聚焦都会立刻触发一次。 */
export const IDLE_INTERVAL_MS = 60_000

/**
 * 下一次 flush 该等多久。
 * 有积压就按队首那条的失败次数退避（1s / 5s / 30s / 2min），
 * 让一次瞬时失败很快重试成功，而不是干等满一分钟。
 */
export async function nextFlushDelayMs(): Promise<number> {
  const [head] = await pendingEntries()
  return head ? backoffDelay(head.attempts) : IDLE_INTERVAL_MS
}

let inFlight = false

/**
 * 只有「重试次数已耗尽」才算错误状态。
 *
 * flushOnce 第一次失败就会返回 stoppedAt（attempts 从 0 变 1），但那只是一次
 * 瞬时失败，队列还会自动重试——顶栏该显示橙点「待同步 N 条」。红点专门留给
 * 卡死的条目（spec §6.4：重试耗尽才转红），否则一断网就立刻变红，
 * 为离线场景专门设计的橙点永远看不到。
 */
function reportResult(result: FlushResult): void {
  const stopped = result.stoppedAt
  if (stopped && stopped.attempts >= MAX_ATTEMPTS) {
    useSyncStore.getState().fail(stopped.lastError ?? '同步失败')
    return
  }
  useSyncStore.getState().succeed()
}

export async function flushAndReport(): Promise<void> {
  if (inFlight) return
  inFlight = true
  useSyncStore.getState().start()

  try {
    reportResult(await flushOnce(supabasePush))
  } finally {
    inFlight = false
  }
}

/** 顶栏橙点/红点点开后的「立即重试」 */
export async function retryNow(): Promise<void> {
  if (inFlight) return
  inFlight = true
  useSyncStore.getState().start()

  try {
    reportResult(await retryAll(supabasePush))
  } finally {
    inFlight = false
  }
}

/**
 * 启动时的三路触发 + 入队通知。返回卸载函数。
 *
 * 用自排期的 setTimeout 而不是 setInterval：间隔取决于队列里队首那条
 * 失败了几次，setInterval 改不了下一次的间隔。
 */
export function startSyncScheduler(): () => void {
  let timer: number | undefined
  let stopped = false

  const schedule = async () => {
    const delay = await nextFlushDelayMs()
    // 等待期间可能已经卸载；顺序也重要——先查再判，避免卸载后仍排一个定时器
    if (stopped) return
    // 必须清掉上一个：启动时那次 run 与联网/聚焦触发的 run 会各自走到这里，
    // 后者把 timer 覆盖成自己的，前者的定时器就此失联——卸载时 clear 不掉，
    // 会在页面已经关掉之后再打一次网络请求
    if (timer !== undefined) window.clearTimeout(timer)
    timer = window.setTimeout(() => void run(), delay)
  }

  const run = async () => {
    await flushAndReport()
    await schedule()
  }

  /** 取消当前等待，立刻跑一次 */
  const trigger = () => {
    if (timer !== undefined) window.clearTimeout(timer)
    void run()
  }

  // 切到后台同样会派发 visibilitychange，只有「重新可见」才该跑
  const onVisibilityChange = () => {
    if (document.visibilityState === 'visible') trigger()
  }

  window.addEventListener('online', trigger)
  window.addEventListener('focus', trigger)
  // 移动端切回标签页不一定触发 window focus，visibilitychange 才可靠（spec §5.3）
  document.addEventListener('visibilitychange', onVisibilityChange)
  // spec §5.3 的第一条触发时机：入队后立即试，不必等兜底轮询
  const offEnqueue = onEnqueue(trigger)
  void run()

  return () => {
    stopped = true
    window.removeEventListener('online', trigger)
    window.removeEventListener('focus', trigger)
    document.removeEventListener('visibilitychange', onVisibilityChange)
    offEnqueue()
    if (timer !== undefined) window.clearTimeout(timer)
  }
}
```

> **为什么单开一个 `ids.ts`**：客户端 UUID 是幂等键（见 Task 6 的 outbox），全项目 4 处要生成（本任务的 `newTile`、Task 10 的保存、Task 12/13 的收款）。而 `crypto.randomUUID()` **只在安全上下文里存在**——生产 https 和本机 localhost 都有，但拿手机连 `vite --host` 时地址是 `http://192.168.x.x`，它是 `undefined`，一按 `[+]` 或保存就抛 TypeError。`crypto.getRandomValues()` 没有这个限制，所以在这里统一兜底，而不是让 4 个调用点各自踩。

`yiji/src/lib/ids.ts`：

```ts
/**
 * 客户端生成的行 UUID：既是目标表主键，也是 outbox 重发的幂等键。
 *
 * 优先用 crypto.randomUUID()，但**只在安全上下文里才有**——https 与 localhost
 * 有，手机连开发机时用的 http://192.168.x.x 没有，那边会直接是 undefined。
 * getRandomValues 不受安全上下文限制，所以拿它兜底；两条路都产出标准 UUID v4。
 */
export function newId(): string {
  if (typeof crypto.randomUUID === 'function') return crypto.randomUUID()

  const bytes = crypto.getRandomValues(new Uint8Array(16))
  // 按 RFC 4122 打上 v4 与 variant 位，否则生成的东西看着像 UUID 但不是
  bytes[6] = (bytes[6] & 0x0f) | 0x40
  bytes[8] = (bytes[8] & 0x3f) | 0x80

  const hex = Array.from(bytes, (b) => b.toString(16).padStart(2, '0')).join('')
  return `${hex.slice(0, 8)}-${hex.slice(8, 12)}-${hex.slice(12, 16)}-${hex.slice(16, 20)}-${hex.slice(20)}`
}
```

`yiji/src/lib/readCache.ts`：

`fetchAndCache` 是 spec §6.1「读取失败绝不白屏」的落点：成功就顺手写一份到 IndexedDB，失败就回落上次缓存，只有连缓存都没有才把错误抛给 Query。

```ts
import { getSupabase } from '@/lib/supabase'
import { db, type TableName } from '@/lib/db'
import type { TileSource } from '@/lib/tiles'

export async function selectAll<T>(table: TableName): Promise<T[]> {
  const { data, error } = await getSupabase().from(table).select('*').returns<T[]>()
  if (error) throw error
  return data
}

export async function fetchAndCache<T>(key: string, loader: () => Promise<T[]>): Promise<T[]> {
  try {
    const rows = await loader()
    await db.readCache.put({ key, rows, fetchedAt: Date.now() })
    return rows
  } catch (error) {
    const cached = await db.readCache.get(key)
    if (cached) return cached.rows as T[]
    throw error
  }
}

export interface RawTileRow {
  id: string
  name: string
  use_count: number
  last_used_at: string
}

export function toTile(row: RawTileRow): TileSource {
  return {
    id: row.id,
    name: row.name,
    useCount: row.use_count,
    lastUsedAt: row.last_used_at,
  }
}
```

```ts
import { getSupabase } from '@/lib/supabase'
import { cutoffISO, todayISO } from '@/lib/dates'
import { toCents } from '@/lib/money'
import { AMOUNT_LOOKBACK_DAYS, topAmountTiles } from '@/lib/tiles'
import { fetchAndCache } from '@/lib/readCache'

interface AmountRow {
  expected_amount: number | string
  work_date: string
}

async function loadRecentAmounts(): Promise<AmountRow[]> {
  const { data, error } = await getSupabase()
    .from('work_records')
    .select('expected_amount, work_date')
    // 与 topAmountTiles 用同一个窗口常量：取窄了会把 tile 的历史截断，
    // 取宽了白拉数据，两处各写一个 30 迟早会分叉
    .gte('work_date', cutoffISO(todayISO(), AMOUNT_LOOKBACK_DAYS))
    .returns<AmountRow[]>()
  if (error) throw error
  return data
}

export function useAmountTiles() {
  const query = useQuery({
    queryKey: ['amount-tiles'],
    queryFn: () => fetchAndCache<AmountRow>('amount-tiles', loadRecentAmounts),
  })

  const history = (query.data ?? []).map((row) => ({
    amountCents: toCents(row.expected_amount),
    workDate: row.work_date,
  }))

  return { ...query, tiles: topAmountTiles(history, todayISO()) }
}
```

```ts
import { enqueue } from '@/lib/outbox'
import { newId } from '@/lib/ids'
import type { TableName } from '@/lib/db'
import type { TileSource } from '@/lib/tiles'

export type TileTable = Extract<TableName, 'clients' | 'locations' | 'work_types'>

export interface NewTileResult {
  id: string
  created: boolean
}

/**
 * 撞 unique(user_id, name) 不报错，直接选中已存在的那个。
 * 先查内存里的磁贴列表而不是等数据库报冲突——离线时根本没有数据库可问。
 */
export async function ensureTile(
  tableName: TileTable,
  rawName: string,
  userId: string,
  existing: TileSource[],
): Promise<NewTileResult> {
  const name = rawName.trim()

  const hit = existing.find((tile) => tile.name === name)
  if (hit) return { id: hit.id, created: false }

  const id = newId()
  const payload: Record<string, unknown> = { id, user_id: userId, name }

  if (tableName === 'work_types') {
    payload.icon = '📌'
    payload.sort_order = existing.length + 1
  } else {
    payload.use_count = 1
    payload.last_used_at = new Date().toISOString()
  }

  await enqueue({ id, op: 'insert', tableName, payload })
  return { id, created: true }
}
```

```ts
import { todayISO } from '@/lib/dates'

export interface Draft {
  workDate: string
  clientId: string | null
  workTypeId: string | null
  title: string
  amountCents: Cents | null
  durationMinutes: number | null
  locationId: string | null
  isCompleted: boolean
  /** 打开时就地展开金额输入，默认填应收全额，到账日期取今天 */
  isPaidNow: boolean
  paidCents: Cents | null
}

/** 不能在模块顶层算死日期，否则跨零点长开的页面会一直停在昨天 */
export function emptyDraft(): Draft {
  return {
    workDate: todayISO(),
    clientId: null,
    workTypeId: null,
    title: '',
    amountCents: null,
    durationMinutes: null,
    locationId: null,
    isCompleted: false,
    isPaidNow: false,
    paidCents: null,
  }
}

export type MissingField = 'clientId' | 'workTypeId' | 'amountCents'

export const MISSING_FIELD_LABEL: Record<MissingField, string> = {
  clientId: '给谁做的',
  workTypeId: '做了什么',
  amountCents: '多少钱',
}

export function missingFields(draft: Draft): MissingField[] {
  const missing: MissingField[] = []
  if (!draft.clientId) missing.push('clientId')
  if (!draft.workTypeId) missing.push('workTypeId')
  // 用 ! 而不是 === null：`toCents('0')` 合法返回 0（解析器不管业务规则），
  // 0 元会撞上库里的 check (expected_amount > 0)。outbox 是串行遇错即停，
  // 一条永远过不了 CHECK 的记录会把后面所有记录的同步全部卡死。
  if (!draft.amountCents) missing.push('amountCents')
  return missing
}

export function missingHint(draft: Draft): string | null {
  const missing = missingFields(draft)
  if (missing.length === 0) return null
  return '还差：' + missing.map((field) => MISSING_FIELD_LABEL[field]).join('、')
}

interface DraftState extends Draft {
  set: (patch: Partial<Draft>) => void
  reset: () => void
}

export const useDraftStore = create<DraftState>((set) => ({
  ...emptyDraft(),
  set: (patch) => set(patch),
  reset: () => set(emptyDraft()),
}))
```

**已知取舍：页面跨零点长开时，日期仍停在昨天。** `emptyDraft()` 里现算日期只解决了 `reset()` 那条路径；store 的**初始**状态是模块加载时求值一次的，之后不会再算。所以速记页整夜挂在同一个标签页里、第二天早上直接记一笔，这一笔会被记成昨天。修法不直观：天真地在 `visibilitychange` 时刷新日期，会把用户**特意选的过去日期**一起冲掉（「补记上周三那笔活」是真实用法），要修得先能区分「日期还是默认值」和「用户改过」，即草稿里多一个 `dateTouched` 标记。紧 MVP 先不做，记在这里。

```ts
import type { QueryClient } from '@tanstack/react-query'
import { enqueue } from '@/lib/outbox'
import { newId } from '@/lib/ids'
import { centsToNumeric } from '@/lib/money'
import { todayISO } from '@/lib/dates'
import { qk } from '@/lib/queryKeys'
import { bumpUsage } from '@/features/tiles/bumpUsage'
import { MISSING_FIELD_LABEL, missingFields, type Draft } from './draftStore'
import type { WorkRecord } from '@/types/models'

export interface SelfLearnCounts {
  /** null 表示这个磁贴是本次刚新建的，insert 已带 use_count=1，不需要再 bump */
  clientUseCount: number | null
  locationUseCount: number | null
}

export interface SaveResult {
  recordId: string
}

export async function saveWorkRecord(
  queryClient: QueryClient,
  draft: Draft,
  userId: string,
  selfLearn: SelfLearnCounts = { clientUseCount: null, locationUseCount: null },
): Promise<SaveResult> {
  // 入口就拦住不完整的草稿。缺 client_id 会撞库里的 not null、金额为 0 会撞
  // check (expected_amount > 0)，而 outbox 是串行遇错即停：一条过不了约束的记录
  // 会把后面所有记录的同步一直堵住，界面上却只是一个红点。宁可在这里大声报错。
  const missing = missingFields(draft)
  if (missing.length > 0) {
    throw new Error('草稿还缺：' + missing.map((field) => MISSING_FIELD_LABEL[field]).join('、'))
  }
  const recordId = newId()
  const now = new Date().toISOString()

  await enqueue({
    id: recordId,
    op: 'insert',
    tableName: 'work_records',
    payload: {
      id: recordId,
      user_id: userId,
      client_id: draft.clientId,
      work_type_id: draft.workTypeId,
      title: draft.title.trim() || null,
      work_date: draft.workDate,
      duration_minutes: draft.durationMinutes,
      location_id: draft.locationId,
      expected_amount: centsToNumeric(draft.amountCents ?? 0),
      is_completed: draft.isCompleted,
    },
  })

  if (draft.isPaidNow && draft.paidCents !== null && draft.paidCents > 0) {
    const paymentId = newId()
    await enqueue({
      id: paymentId,
      op: 'insert',
      tableName: 'payments',
      payload: {
        id: paymentId,
        user_id: userId,
        work_record_id: recordId,
        amount: centsToNumeric(draft.paidCents),
        received_at: todayISO(),
      },
    })
  }

  if (draft.clientId && selfLearn.clientUseCount !== null) {
    await bumpUsage('clients', draft.clientId, selfLearn.clientUseCount)
  }
  if (draft.locationId && selfLearn.locationUseCount !== null) {
    await bumpUsage('locations', draft.locationId, selfLearn.locationUseCount)
  }

  const optimistic: WorkRecord = {
    id: recordId,
    user_id: userId,
    client_id: draft.clientId ?? '',
    work_type_id: draft.workTypeId ?? '',
    title: draft.title.trim() || null,
    work_date: draft.workDate,
    duration_minutes: draft.durationMinutes,
    location_id: draft.locationId,
    expected_amount: centsToNumeric(draft.amountCents ?? 0),
    is_completed: draft.isCompleted,
    created_at: now,
    updated_at: now,
  }

  queryClient.setQueryData<WorkRecord[]>(qk.workRecords, (old) => [optimistic, ...(old ?? [])])
  void queryClient.invalidateQueries({ queryKey: qk.unpaid })
  void queryClient.invalidateQueries({ queryKey: qk.amountTiles })

  return { recordId }
}
```

```tsx
import { create } from 'zustand'
import { useEffect } from 'react'

interface ToastState {
  message: string | null
  show: (message: string) => void
  hide: () => void
}

export const useToastStore = create<ToastState>((set) => ({
  message: null,
  show: (message) => set({ message }),
  hide: () => set({ message: null }),
}))

export function Toaster() {
  const message = useToastStore((s) => s.message)
  const hide = useToastStore((s) => s.hide)

  useEffect(() => {
    if (!message) return
    const timer = window.setTimeout(hide, 1800)
    return () => window.clearTimeout(timer)
  }, [message, hide])

  if (!message) return null

  return (
    <div
      role="status"
      className="fixed bottom-24 left-1/2 z-50 -translate-x-1/2 rounded-full bg-gray-900 px-4 py-2 text-sm text-white"
    >
      {message}
    </div>
  )
}
```

spec §4.3：按日期分组倒序；卡片第二行「时长 · 地点 · 完成标记」，字段为空则整段省略；左滑露出「收款」「完成」；顶部筛选 chips `全部 / 未收款 / 已完成 / 本月`。

> **实作记录与已知局限（2026-09-15，`cff7d81`）**
>
> - **页面测试冻结了 `Date`。** 计划里的 `LedgerPage.test.tsx` 把日期写死成 `2026-09-12`，而页面读 `todayISO()`，于是那个测试**只在 9 月 12 日当天能过**。已在 `beforeAll/afterAll` 里只冻结 `Date`（断言一个字没动）。日后写涉及「今天」的页面测试都要注意这一点；`groupByDate(records, today)` 本身是注入式的，纯函数测试没这个问题。
> - **左滑只有指针事件，且没有和浏览器抢手势。** 没有 `touch-action: pan-y`、没有 `preventDefault`，也没有 `setPointerCapture`：横向拖动会和浏览器自身的平移、以及 iOS 的**边缘返回手势**打架（从左边缘起手的左滑正好就是返回手势），浏览器会接管并触发 `pointercancel`，卡片静默弹回；手指移出卡片边界（192px 很容易超出）会让拖动卡住。三个动作按钮始终在 DOM 里，所以 Tab 能聚焦、Enter 能触发——算一条键盘通路，但焦点不可见、没有 `aria-expanded`，也没有任何键盘方式把卡片滑开。滑开的卡片不会自动关、可以同时开多张、没有点击空白处关闭。
> - **`deleteRecord` 的「会连带删几笔」是前端估算，而库侧是无条件级联。** 有服务端独有的收款（别的设备记的、或 refetch 掉了乐观行）时会**少报**；乐观行的 outbox 条目被 `discard` 过时会**多报**。顺序是安全的（弹层挡住卡片，insert 必然先于 delete），不会留下外键断裂的 insert。另外 `deleteRecord` 没有 invalidate `qk.payments`。
> - **流水屏 import 了 Task 13 的 `PaymentSheet` / `recordPayment`**，原任务顺序不成立——详见 Task 13 开头的顺序修正说明。

```ts
import { getSupabase } from '@/lib/supabase'
import { fetchAndCache } from '@/lib/readCache'
import { qk } from '@/lib/queryKeys'
import { toCents, type Cents } from '@/lib/money'
import type { Payment } from '@/types/models'

async function loadPayments(): Promise<Payment[]> {
  const { data, error } = await getSupabase()
    .from('payments')
    .select('*')
    .returns<Payment[]>()
  if (error) throw error
  return data
}

export function usePayments() {
  return useQuery({
    queryKey: qk.payments,
    queryFn: () => fetchAndCache<Payment>('payments', loadPayments),
  })
}

/** 按 work_record_id 聚合已收金额，收款状态一律现算不存库 */
export function sumPaidByRecord(payments: Payment[]): Map<string, Cents> {
  const totals = new Map<string, Cents>()
  for (const payment of payments) {
    const prev = totals.get(payment.work_record_id) ?? 0
    totals.set(payment.work_record_id, prev + toCents(payment.amount))
  }
  return totals
}
```

```ts
export function formatDuration(minutes: number): string {
  const hours = Math.floor(minutes / 60)
  const rest = minutes % 60
  if (hours === 0) return `${rest}min`
  if (rest === 0) return `${hours}h`
  return `${hours}h${rest}min`
}

export interface RecordLineInput {
  durationMinutes: number | null
  locationName: string | null
  isCompleted: boolean
}

/** 空字段整段省略而不是留「-」占位；三项全空返回 null，调用方据此不渲染第二行 */
export function recordLine(input: RecordLineInput): string | null {
  const parts: string[] = []

  if (input.durationMinutes !== null) parts.push(formatDuration(input.durationMinutes))
  if (input.locationName) parts.push(input.locationName)
  if (input.isCompleted) parts.push('✓已完成')

  return parts.length === 0 ? null : parts.join(' · ')
}
```

```ts
import type { WorkRecord } from '@/types/models'

export type LedgerFilter = 'all' | 'unpaid' | 'completed' | 'thisMonth'

export const FILTER_ORDER: LedgerFilter[] = ['all', 'unpaid', 'completed', 'thisMonth']

export const FILTER_LABELS: Record<LedgerFilter, string> = {
  all: '全部',
  unpaid: '未收款',
  completed: '已完成',
  thisMonth: '本月',
}

export interface FilterContext {
  /** 由 payments + derivePaymentStatus 现算，不在前端存状态、也不跨 feature 去读 v_unpaid */
  unpaidIds: Set<string>
  today: string
}

export function applyFilter(
  records: WorkRecord[],
  filter: LedgerFilter,
  ctx: FilterContext,
): WorkRecord[] {
  if (filter === 'all') return records

  const monthPrefix = ctx.today.slice(0, 7)

  return records.filter((record) => {
    if (filter === 'unpaid') return ctx.unpaidIds.has(record.id)
    if (filter === 'completed') return record.is_completed
    return record.work_date.startsWith(monthPrefix)
  })
}
```

```ts
import type { QueryClient } from '@tanstack/react-query'
import { enqueue } from '@/lib/outbox'
import { qk } from '@/lib/queryKeys'
import type { WorkRecord } from '@/types/models'

function patchCache(
  queryClient: QueryClient,
  update: (records: WorkRecord[]) => WorkRecord[],
): void {
  queryClient.setQueryData<WorkRecord[]>(qk.workRecords, (old) => update(old ?? []))
  void queryClient.invalidateQueries({ queryKey: qk.unpaid })
}

export async function toggleCompleted(
  queryClient: QueryClient,
  record: WorkRecord,
): Promise<void> {
  const next = !record.is_completed

  await enqueue({
    id: record.id,
    op: 'update',
    tableName: 'work_records',
    payload: { is_completed: next },
  })

  patchCache(queryClient, (records) =>
    records.map((r) => (r.id === record.id ? { ...r, is_completed: next } : r)),
  )
}

export async function deleteRecord(
  queryClient: QueryClient,
  record: WorkRecord,
): Promise<void> {
  // payments 的 on delete cascade 在数据库侧，客户端只需要删父行
  await enqueue({ id: record.id, op: 'delete', tableName: 'work_records', payload: {} })

  patchCache(queryClient, (records) => records.filter((r) => r.id !== record.id))
}

export function deleteConfirmText(paymentCount: number): string {
  const cascade = paymentCount > 0 ? `同时删除 ${paymentCount} 笔收款记录，` : ''
  return `删除这条记录？${cascade}不可恢复。`
}
```

```ts
import { cutoffISO } from '@/lib/dates'
import type { WorkRecord } from '@/types/models'

export interface DateGroup {
  date: string
  label: string
  records: WorkRecord[]
}

export function groupLabel(isoDate: string, today: string): string {
  const [, month, day] = isoDate.split('-')
  const base = `${Number(month)}月${Number(day)}日`

  if (isoDate === today) return `今天 ${base}`
  if (isoDate === cutoffISO(today, 1)) return `昨天 ${base}`
  return base
}

export function groupByDate(records: WorkRecord[], today: string): DateGroup[] {
  const buckets = new Map<string, WorkRecord[]>()

  for (const record of records) {
    const bucket = buckets.get(record.work_date)
    if (bucket) bucket.push(record)
    else buckets.set(record.work_date, [record])
  }

  // ISO 日期字符串可直接按字典序比倒序，无需解析成 Date
  return [...buckets.entries()]
    .sort((a, b) => (a[0] < b[0] ? 1 : -1))
    .map(([date, rows]) => ({ date, label: groupLabel(date, today), records: rows }))
}
```

```ts
import { useQuery } from '@tanstack/react-query'
import { getSupabase } from '@/lib/supabase'
import { fetchAndCache } from '@/lib/readCache'
import { qk } from '@/lib/queryKeys'
import { toCents, type Cents } from '@/lib/money'
import type { UnpaidRow } from '@/types/models'

async function loadUnpaid(): Promise<UnpaidRow[]> {
  const { data, error } = await getSupabase()
    .from('v_unpaid')
    .select('*')
    .order('days_overdue', { ascending: false })
    .returns<UnpaidRow[]>()
  if (error) throw error
  return data
}

export function useUnpaid() {
  return useQuery({
    queryKey: qk.unpaid,
    queryFn: () => fetchAndCache<UnpaidRow>('unpaid', loadUnpaid),
  })
}

export interface UnpaidSummary {
  totalCents: Cents
  count: number
  worst: UnpaidRow | null
}

/** 入参已按 days_overdue 降序，第一条就是拖最久的 */
export function summarizeUnpaid(rows: UnpaidRow[]): UnpaidSummary {
  let totalCents: Cents = 0
  for (const row of rows) totalCents += toCents(row.outstanding_amount)

  return { totalCents, count: rows.length, worst: rows[0] ?? null }
}
```

```ts
import type { QueryClient } from '@tanstack/react-query'
import { enqueue } from '@/lib/outbox'
import { newId } from '@/lib/ids'
import { centsToNumeric } from '@/lib/money'
import { qk } from '@/lib/queryKeys'
import type { Cents } from '@/lib/money'
import type { Payment } from '@/types/models'

export interface RecordPaymentInput {
  workRecordId: string
  userId: string
  amountCents: Cents
  receivedAt: string
}

/** 一条工作挂 N 笔收款，所以这里永远是追加，不改 work_records */
export async function recordPayment(
  queryClient: QueryClient,
  input: RecordPaymentInput,
): Promise<string> {
  const paymentId = newId()

  await enqueue({
    id: paymentId,
    op: 'insert',
    tableName: 'payments',
    payload: {
      id: paymentId,
      user_id: input.userId,
      work_record_id: input.workRecordId,
      amount: centsToNumeric(input.amountCents),
      received_at: input.receivedAt,
    },
  })

  const optimistic: Payment = {
    id: paymentId,
    user_id: input.userId,
    work_record_id: input.workRecordId,
    amount: centsToNumeric(input.amountCents),
    received_at: input.receivedAt,
    created_at: new Date().toISOString(),
  }

  queryClient.setQueryData<Payment[]>(qk.payments, (old) => [...(old ?? []), optimistic])
  void queryClient.invalidateQueries({ queryKey: qk.unpaid })
  void queryClient.invalidateQueries({ queryKey: qk.workRecords })

  return paymentId
}
```

```tsx
 * 代价是**调用点必须给本组件加 `key={row?.id}`**：换一条记录时靠重新挂载拿到
 * 新的初始值，否则会留着上一条的金额。
 */
export function PaymentSheet({ row, onClose, onConfirm }: PaymentSheetProps) {
  const outstanding = row ? toCents(row.outstanding_amount) : 0
  const [amountText, setAmountText] = useState(() =>
    row ? formatYuanPlain(toCents(row.outstanding_amount)) : '',
  )
  const [receivedAt, setReceivedAt] = useState(() => todayISO())

  if (!row) return null

  let amountCents: Cents | null = null
  try {
    amountCents = toCents(amountText)
  } catch {
    amountCents = null
  }

  // 收款超过应收是允许的（客户多付、含税差异），这里只做下限校验；
  // 与 expected 的比较（多收多少）由 derive.overpaidCents 负责
  const error = amountCents === null ? '请输入金额' : validatePaymentAmount(amountCents)

  const quickAmounts = [outstanding, Math.round(outstanding / 2)]

  return (
    <Sheet open title="记一笔收款" onClose={onClose}>
      <div className="flex flex-col gap-3">
        <p className="text-sm text-gray-500">
          {row.client_name} · 还差 {formatYuan(outstanding)}
        </p>

        <div className="flex gap-2">
          {quickAmounts.map((cents) => (
            <Tile
              key={cents}
              label={formatYuanShort(cents)}
              selected={amountCents === cents}
              onSelect={() => setAmountText(formatYuanPlain(cents))}
            />
          ))}
        </div>

        <label className="flex flex-col gap-1 text-xs text-gray-500">
          金额（元）
          <input
            value={amountText}
            onChange={(event) => setAmountText(event.target.value)}
            inputMode="decimal"
            className="h-11 rounded-xl border border-gray-200 px-3 text-base text-gray-900"
          />
        </label>

        <label className="flex flex-col gap-1 text-xs text-gray-500">
          到账日期
          <input
            type="date"
            value={receivedAt}
            onChange={(event) => setReceivedAt(event.target.value)}
            className="h-11 rounded-xl border border-gray-200 px-3 text-base text-gray-900"
          />
        </label>

        {error && <p className="text-sm text-red-600">{error}</p>}

        <Button
          onClick={() => {
            if (amountCents === null || error) return
            onConfirm(amountCents, receivedAt)
          }}
          disabled={amountCents === null || error !== null}
        >
          确认收款
        </Button>
      </div>
    </Sheet>
  )
}
```

```tsx
import { useQueryClient } from '@tanstack/react-query'

  const queryClient = useQueryClient()
  const userId = useAuthStore((s) => s.userId)
  const showToast = useToastStore((s) => s.show)
  const unpaid = useUnpaid()

  const [sheetRow, setSheetRow] = useState<UnpaidRow | null>(null)

      workDate: row.work_date,

}
```

```ts
interface NetworkState {
  /** 当前展示的数据来自 IndexedDB 缓存而不是网络 */
  degraded: boolean
  setDegraded: (degraded: boolean) => void
}

export const useNetworkStore = create<NetworkState>((set) => ({

  // 同值不写回：一屏可能并发跑四五个 query，每个都 set 一遍会白白触发重渲染
  setDegraded: (degraded) => set((state) => (state.degraded === degraded ? state : { degraded })),
}))
```

```ts
export async function fetchAndCache<T>(key: string, loader: () => Promise<T[]>): Promise<T[]> {
  try {
    const rows = await loader()
    await db.readCache.put({ key, rows, fetchedAt: Date.now() })
    useNetworkStore.getState().setDegraded(false)
    return rows
  } catch (error) {
    const cached = await db.readCache.get(key)

      useNetworkStore.getState().setDegraded(true)
      return cached.rows as T[]
    }
    throw error
  }
}
```

```tsx
import { useState } from 'react'
import { useLiveQuery } from 'dexie-react-hooks'
import { db } from '@/lib/db'
import { MAX_ATTEMPTS, discard } from '@/lib/outbox'
import { retryNow } from '@/lib/syncScheduler'
import { useSyncStore } from '@/features/sync/syncStore'

const TABLE_LABEL: Record<string, string> = {
  clients: '客户',
  work_types: '类型',
  locations: '地点',
  work_records: '记录',
  payments: '收款',
}

export function SyncIndicator() {
  const status = useSyncStore((s) => s.status)
  const lastError = useSyncStore((s) => s.lastError)
  const [open, setOpen] = useState(false)
  // 只传 querier，不传 deps/defaultResult——不同版本的 dexie-react-hooks 这两个参数顺序不一样
  const pending = useLiveQuery(() => db.outbox.count()) ?? 0
  // 卡死的条目：重试次数已耗尽，自动重试不会再碰它，只能靠用户丢弃
  const stuck =
    useLiveQuery(() => db.outbox.filter((e) => e.attempts >= MAX_ATTEMPTS).toArray(), []) ?? []

  async function onDiscard(seq: number) {
    await discard(seq)
    // 摘掉之后后面的条目才有机会走，立刻再试一次，别等下一个兜底周期
    await retryNow()
  }

  if (status === 'error') {
    return (
      <div className="relative">
        <button
          type="button"
          onClick={() => setOpen((v) => !v)}
          aria-expanded={open}
          className="flex items-center gap-1.5 rounded-full px-2 py-1 text-xs text-red-600"
        >
          <span className="size-2 rounded-full bg-red-500" aria-hidden />
          同步失败 · 查看
        </button>

        {open && (
          <section className="absolute right-0 top-full z-10 mt-1 w-72 rounded-xl border border-red-200 bg-white p-3 text-xs shadow-lg">
            {/* 原因必须是可见文本：放在 title 里移动端根本 hover 不出来 */}
            <p className="break-words text-red-600">{lastError ?? '同步失败'}</p>

            {stuck.length > 0 && (
              <ul className="mt-2 flex flex-col gap-2">
                {stuck.map((entry) => (
                  <li key={entry.seq} className="flex items-center justify-between gap-2">
                    <span className="truncate text-gray-600">
                      {TABLE_LABEL[entry.tableName] ?? entry.tableName} · {entry.id.slice(0, 8)}
                    </span>
                    <button
                      type="button"
                      onClick={() => void onDiscard(entry.seq!)}
                      className="shrink-0 rounded-lg px-2 py-1 text-red-600 underline"
                    >
                      丢弃
                    </button>
                  </li>
                ))}
              </ul>
            )}

            <button
              type="button"
              onClick={() => void retryNow()}
              className="mt-2 w-full rounded-lg bg-gray-900 py-1.5 text-white"
            >
              立即重试
            </button>
          </section>
        )}
      </div>
    )
  }

  if (pending > 0) {
    return (
      <button
        type="button"
        onClick={() => void retryNow()}
        className="flex items-center gap-1.5 rounded-full px-2 py-1 text-xs text-amber-600"
      >
        <span className="size-2 rounded-full bg-amber-400" aria-hidden />
        待同步 {pending} 条
      </button>
    )
  }

  return (
    <span className="flex items-center gap-1.5 px-2 py-1 text-xs text-gray-400">
      <span className="size-2 rounded-full bg-gray-300" aria-hidden />
      已同步
    </span>
  )
}
```

红点优先级高于橙点：`status === 'error'` 时哪怕队列里还堆着 20 条，也只显示「同步失败」——用户要看到的是「出事了，点这里」，不是数字。

红点展开面板是卡死队列的**唯一**出路：串行遇错即停之下，一条重试耗尽的条目会挡住后面所有记录，而 `retryAll` 清零重推对它无效（还是同一条错误）。所以面板要同时给出「原因」「是哪一条」「丢弃」和「立即重试」——只给重试按钮等于没有出路。

```tsx
  if (!userId && stopScheduler) {
    stopScheduler()
    stopScheduler = null
  }
}

    </Providers>
  </StrictMode>,
)
```

## 最终整体审查（2026-09-16，14 个任务全部实现后）

逐任务审查已经把每个模块单独看过一遍；这一轮专门看**跨模块**的问题——那是逐任务审查结构上看不到的。结论：**代码可以交付，但有三件事应当在算「完成」之前修掉**。

### 必修（都撞在核心场景上，不是新需求）

**1. 离线时读路径完全不认识 outbox，已记下的账会从列表里消失。**
`fetchAndCache` 在读取失败且缓存命中时**把缓存当成功返回**（`readCache.ts:18-25`），而读缓存只在网络成功时才写入。于是：离线记的那一笔在流水里看不到（`v_unpaid` 是服务端的，所以未收款、合计、Tab 角标也都没有它）；更糟的是查询超过 30 秒变陈旧、离线重取时，缓存把乐观更新**覆盖回修改前的样子**——离线记的消失、离线删的复活、离线改「完成」的回退，而 outbox 里明明还留着它们。用户看到会以为没记上，**于是再记一遍，账就重了**。
突破口：flush 成功后反向 invalidate 并 patch 查询缓存；或者在读路径里把 outbox 的待推送条目合并进结果。spec §6.2 说「写失败对用户不可见」，但不该连「写成功但还没同步」也看不见。

**2. 读取失败被渲染成「一切正常」。**
无缓存时 `readCache.ts:24` 直接抛给 Query，而三个消费点都没看 `isError`：流水显示「还没有记录」（`LedgerPage.tsx:129`）、未收款显示「全都收到了 🎉」（`UnpaidPage.tsx:26-33`）、角标显示 0（`TabBar.tsx:13`）。网络故障看起来像「你没有活干、客户都付清了」，而且此时**连离线横幅都不显示**（`networkStore` 只在缓存命中时才置位）。spec §6.1 要的是「读取失败绝不白屏」，现在的失败态不是白屏，是**假的好消息**。

### Task 15: 读路径合并 outbox 的待推送条目

本轮最要紧的一条。`fetchAndCache` 在失败且缓存命中时把缓存当成功返回（`readCache.ts:18-25`），而缓存只在网络成功时写入——于是离线记的那笔在流水里看不见；查询变陈旧后离线重取还会用缓存**覆盖掉乐观更新**（离线记的消失、离线删的复活），用户以为没记上就再记一遍，账重了。同一机制也让离线新建的客户从磁贴墙上消失，进而诱导重复新建同名客户——那正好撞上已知的重名卡死路径。

**做法**：`fetchAndCache` 拿到 rows 之后（无论是刚取的还是回落的），按该 key 对应的表把 outbox 里还没推上去的条目叠加上去：insert 补行、update 打补丁、delete 剔除，严格按 `seq` 顺序。于是「服务端数据 + 本地待推送」拼成用户实际该看到的视图。

**Files:**
- Create: `yiji/src/lib/pendingOverlay.ts`
- Test: `yiji/src/lib/pendingOverlay.test.ts`
- Modify: `yiji/src/lib/readCache.ts`、`yiji/src/lib/readCache.test.ts`

**刻意不覆盖 `unpaid`**：它的行是 `v_unpaid` 的派生形状（`client_name` / `days_overdue` / `outstanding_amount`），在客户端叠出来就得重算拖欠天数与未收金额——那正是 spec §5.4 明确不让前端做的事。所以**未收款屏与合计/角标只反映已同步的数据**，离线新建的那笔要等同步后才出现。这条取舍必须写进代码注释，免得后人以为是漏了。

**测试契约（`pendingOverlay.test.ts`，6 条）**：

```ts
import { beforeEach, describe, expect, it } from 'vitest'
import { db } from '@/lib/db'
import { enqueue } from '@/lib/outbox'
import { applyPendingOverlay } from './pendingOverlay'

const row = (id: string, extra: Record<string, unknown> = {}) => ({ id, name: id, ...extra })

beforeEach(async () => {
  await db.outbox.clear()
})

describe('applyPendingOverlay', () => {
  it('把还没推上去的 insert 补进结果', async () => {
    await enqueue({ id: 'c2', op: 'insert', tableName: 'clients', payload: { id: 'c2', name: '李四' } })
    const rows = await applyPendingOverlay('clients', [row('c1')])
    expect(rows.map((r) => r.id)).toEqual(['c1', 'c2'])
  })

  it('把还没推上去的 delete 剔掉——否则离线删掉的记录会复活', async () => {
    await enqueue({ id: 'c1', op: 'delete', tableName: 'clients', payload: {} })
    const rows = await applyPendingOverlay('clients', [row('c1'), row('c2')])
    expect(rows.map((r) => r.id)).toEqual(['c2'])
  })

  it('update 只打补丁，不整行替换（服务端那行还有别的列）', async () => {
    await enqueue({
      id: 'c1',
      op: 'update',
      tableName: 'clients',
      payload: { use_count: 5, last_used_at: 'x' },
    })
    const [merged] = await applyPendingOverlay('clients', [row('c1', { use_count: 4 })])
    expect(merged).toMatchObject({ id: 'c1', name: 'c1', use_count: 5, last_used_at: 'x' })
  })

  it('同一行先 insert 后 delete，叠加后应当不存在', async () => {
    await enqueue({ id: 'c9', op: 'insert', tableName: 'clients', payload: { id: 'c9' } })
    await enqueue({ id: 'c9', op: 'delete', tableName: 'clients', payload: {} })
    expect(await applyPendingOverlay('clients', [])).toEqual([])
  })

  it('只吃自己那张表的条目，不串台', async () => {
    await enqueue({ id: 'w1', op: 'insert', tableName: 'work_types', payload: { id: 'w1' } })
    expect(await applyPendingOverlay('clients', [])).toEqual([])
  })

  it('没有待推送条目时原样返回', async () => {
    const rows = [row('c1')]
    expect(await applyPendingOverlay('clients', rows)).toEqual(rows)
  })
})
```

`readCache.test.ts` 追加两条：**回落缓存时也要叠加**（离线新建的客户不会从磁贴墙上消失）；`unpaid` 这类派生 key 不做叠加。

**实现要点**：`fetchAndCache` 是异步的，叠加必须在拿到 rows 之后、`return` 之前做。**不要试图在 loader 里做**——回落路径根本不经过 loader。

已完成，222 个测试。审查逐步走通了「离线记 → 陈旧后离线重取」与「离线删 → 同上」两条路径，确认修复生效；也确认所有原始表的写入（`bumpUsage` 的 update、`toggleCompleted`、记录的 insert、收款的 insert、删除）都被覆盖。

**审查新发现的后续项（记下来，本轮不修）**

1. **离线删了记录、却还能对它收一笔款 → 队列卡死**（值得优先处理）。删除只入队 `work_record` 的 delete，本地不动 `payments`；而未收款屏读的是服务端视图，那一条还在，于是用户能对它收款 → 队列里 delete 在前、payment insert 在后 → 后者撞外键（23503）→ 串行遇错即停把后面全堵住。这正是我们花力气给「卡死队列」做逃生出口的那条路径。修法二选一：收款前查一下 outbox 里有没有该记录的待删除条目并拒绝，或让推送把 23503 当成「不可重试」直接丢弃该条。
2. **离线新增的记录落在所属日期分组的最后**（插入是追加的，而服务端按 `work_date desc, created_at desc` 排）。可见但不影响正确性——重复记账的危害已经没了，只是位置不对。
3. **`enqueue` 与 `setQueryData` 之间的窄竞态**：若在这两步之间 `workRecords` 恰好 refetch（聚焦/联网都会触发），快照与乐观行可能各有一条同 id 的行，短暂出现重复卡片。
4. **推送成功后没有 invalidate**，而读缓存只在读取成功时才写：于是已同步的记录在「推送成功」到「下次读取成功」之间，若离线回落重取，仍可能消失——原缺陷的更窄版本。修法是 flush 成功后按涉及的表 invalidate 对应查询键。

### Task 18: 堵住「离线删了记录却还能对它收款」这条卡死入口

1. **未收款屏不再列出有待删除父记录的行。** 这是**过滤**不是叠加：只按 id 剔除，不重算拖欠天数与未收金额，所以不违反 spec §5.4。放在 `readCache.ts` 里对 `unpaid` 这个键统一处理（而不是只在 `useUnpaid` 里做），因为将来若有第二个消费点就会漏。同时更新那段注释：`unpaid` 不做**叠加**，但做**剔除**。
2. **`recordPayment` 入口拒绝。** 即使过滤还没重跑（竞态），也不能让这笔进队列：入队前查 outbox 里有没有该 `work_records` 的待删除条目，有就抛错。调用点（未收款屏的 `onConfirm`）必须接住并提示——这条依赖 Task 16 的错误提示通路。
